# 传输适配与验证

## `MessageFrame`

`MessageFrame` 是当前唯一的线上帧模型，也是帧格式的唯一事实来源。

帧格式固定为：

```text
2 bytes length + 1 byte messageId + payload
```

它明确承担三件事：

- `NetMessage <-> MessageFrame` 转换
- `MessageFrame <-> packet bytes` 转换
- 分包 / 粘包读取支持

## 为什么 `MessageFrame` 独立存在

这样拆分是为了保持边界稳定：

- `NetMessage` 只表示消息体
- `MessageFrame` 承担线上封包格式
- 协议层不关心 TCP 长度前缀

这样可以避免 TCP 细节污染协议层和运行时层。

## Reader / Writer

### `MessageFrame.Reader`

读取器内部维护缓冲区，支持把多次收到的字节追加进去，再持续解析完整帧。

当前行为包括：

- 至少拿到 2 个字节才开始判断帧长
- 帧长小于 `3` 直接报错
- 缓冲区不足一个完整帧时继续等待
- 一次 `Append(...)` 可以产出多个完整帧

这使它可以直接处理 TCP 常见的拆包和粘包场景。

### `MessageFrame.Writer`

写入器负责把：

- `NetMessage`
- `SendNetMessage`

统一编码成线上字节数组。

## TCP 适配层定位

`MessageTcpServer`、`MessageTcpSession`、`MessageTcpClient` 位于传输适配层。

这一层的职责是：

- 接收和发送 TCP 字节流
- 调用 `MessageFrame.Reader` / `Writer`
- 把传输世界对接到内部消息模型

它不负责定义协议字段，也不负责决定消息是否允许被某个会话处理。

## `13` 号包样例定位

`Packet13VerificationNotes.md` 已经明确退回为“单样例验证笔记”，不再承担总设计文档角色。

它当前主要证明：

- `PacketDefinition + PacketCodec` 可以表达复杂旧协议结构
- 条件字段和字段组模型方向可行

但它还没有覆盖：

- 会话阶段门禁
- 完整连接状态机

- 新旧协议全量迁移顺序
