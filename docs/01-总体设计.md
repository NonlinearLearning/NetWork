# 总体设计

## 当前组织方式

仓库按语义原型组织，而不是按一个共享生产层组织：

```text
NetWork/
├─ Prototypes/
│  ├─ external-context-wire-submission/
│  ├─ graph-layout-codegen/
│  ├─ packet-layout-ast/
│  ├─ packet13-segment-codec/
│  ├─ packet20-local-state/
│  ├─ packet88-performance/
│  ├─ slot-graph-ir/
│  ├─ typed-span-sourcegen/
│  └─ ...
└─ docs/
```

完整目录、入口和验证状态见 [Prototypes/README.md](../Prototypes/README.md)。仓库不保留共享顶层 `Core/`；每个原型拥有自己的源码、项目、验证和生成产物。即便某个原型接近生产形态，也只在自己的实验目录内成立。

## 原型边界

- 概念问题先写设计 MD，再写执行 MD，最后按执行 MD 迁移和验证。
- 一个概念探索对应一个语义目录，不使用 `prototype1`、`prototype2` 这类编号目录。
- 原型之间不建立跨顶层 `ProjectReference`，也不通过跨顶层 `Compile Include` 共享源码。
- 重复最小运行时或测试辅助代码是隔离的有意代价，不再通过 `Core`、`Common` 或隐藏基础 runtime 消除重复。
- `external-context-wire-submission` 是完整度最高的实验原型，不是新生产主干。

## 主要实验关系

`external-context-wire-submission` 研究外部上下文到不可变 wire submission 的边界；`packet13-segment-codec` 和 `packet20-local-state` 分别把这个问题缩小到固定/有界 segment 与 Packet 20 局部状态。`minimal-dependency-graph`、`packet-layout-ast`、`graph-layout-codegen`、`slot-graph-ir` 和 `typed-span-sourcegen` 分别探索依赖图、声明语义、代码生成、slot IR 和 source generation；`packet88-performance` 只做 codec 对照和测量。

这些原型可以互相提供设计证据，但不能互相作为源码或程序集依赖。
